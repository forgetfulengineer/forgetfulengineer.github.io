【PHP】執行環境與 SAPI（Server API）

2026-11-23-回覆文章分享

本篇重點

  • PHP 是程式語言，PHP Runtime 是實際提供程式執行能力的環境
  • Zend Engine 是 PHP Runtime 的核心，負責 PHP 程式碼的解析、編譯與執行
  • SAPI 是 PHP Runtime 與外部執行環境之間的整合介面
  • CLI、CGI、FPM 是不同的 SAPI 實作，適用於不同的執行場景
  • PHP CLI 可以直接在作業系統的命令列環境中執行 PHP 程式
  • PHP-FPM 是以 FastCGI 為基礎的 PHP Process Manager，並不是 PHP Runtime

平常開發 PHP 應用程式時，主要接觸的是 PHP 語法、框架與應用程式邏輯，例如 Laravel 或原生 PHP。但 PHP 程式碼本身並不能直接被 CPU 執行，必須透過 PHP Runtime 提供的執行環境，才能將程式碼解析並執行。

PHP 執行環境

PHP 程式碼（.php 檔）只是文字檔，必須由執行環境處理後才會產生結果。執行架構可以區分為：

名稱定位
PHP程式語言及其語法
PHP Runtime提供 PHP 程式執行所需的環境，包含 Zend Engine、PHP Core 與 Extension
Zend Engine負責解析、編譯與執行 PHP 程式的核心引擎
PHP Extension擴充 PHP Runtime 功能的模組，例如 mysqli、PDO、curl
PHP Core提供 php.ini 設定、輸出層、Streams 等基礎功能

PHP Runtime 與 Zend Engine

PHP Runtime 是 PHP 程式實際執行時所依賴的環境，由 Zend Engine、PHP Core 與 PHP Extension 組成。

其中，Zend Engine 是 PHP Runtime 的核心元件，主要負責：

  • 解析 PHP 原始碼
  • 將 PHP 程式碼轉換為可供執行的內容
  • 執行程式指令
  • 管理變數、型別、記憶體及物件等執行期間的資料

PHP 程式碼會經過 Zend Engine 的處理，並由 PHP Runtime 提供完整的執行環境。

PHP Extension

PHP Extension（擴充套件）用來擴充 PHP Runtime 的功能，讓 PHP 能夠使用核心以外的功能或整合外部資源。

常見的擴充套件

Extension用途
PDO提供統一的資料庫連線與操作介面
mysqli用於連線及操作 MySQL 資料庫
mbstring提供多位元組字串處理功能
curl發送 HTTP 請求，與外部 API 或網站進行資料交換

Extension 並不是獨立的 PHP 執行環境，而是由 PHP Runtime 載入，提供額外的函式、類別及功能。

PHP 是否一定需要 Web Server？

PHP 不一定需要 Web Server

PHP 常見的執行場景可以分成兩種：

  • 命令列執行： 透過 PHP CLI 執行程式，不需要 Web Server，例如排程及 Laravel Artisan
  • Web 請求執行： 透過 Web Server 搭配 PHP 的 Web SAPI 處理 HTTP 請求，例如 Nginx 搭配 PHP-FPM

因此 PHP 語言本身並不依賴 HTTP 或 Web Server。Web Server 只是 PHP 在 Web 應用程式場景中的一種整合方式。

什麼是 SAPI？

SAPI（Server Application Programming Interface，伺服器應用程式介面）是 PHP Runtime 與外部執行環境之間的整合層。

PHP 透過 SAPI 提供對應的介面處理不同環境的輸入、輸出及整合

  • CLI 需要接收命令列參數，並將執行結果輸出至終端機
  • CGI 需要接收 Web Server 提供的請求資訊，並將執行結果交還給 Web Server
  • FPM 需要提供 FastCGI 執行環境，讓 Web Server 能夠將請求交由 PHP 處理

SAPI 在 PHP 架構中的定位

SAPI 可以理解為 PHP Runtime 的入口與外部整合層，負責將不同執行環境所提供的資訊轉換成 PHP Runtime 可以使用的形式，並將 PHP 的執行結果交回對應環境。

例如

  • CLI SAPI 負責處理命令列參數及終端機輸出
  • CGI SAPI 負責處理 CGI 環境提供的請求資訊
  • FPM SAPI 負責整合 FastCGI 執行環境

SAPI 並不負責 PHP 語言本身的程式執行邏輯，實際執行工作仍由 PHP Runtime 中的 Zend Engine 負責。

為什麼需要不同的 SAPI？

不同執行環境需要的系統資源及輸入輸出方式不同，如果每種環境都必須重新實作 PHP 的程式執行引擎，將會產生大量重複工作。

透過 SAPI，可以讓 PHP Runtime 維持相同的核心執行能力，再由不同 SAPI 負責整合外部環境。

這代表同一份 PHP 程式碼，可以在不同 SAPI 下執行，而不需要因為執行環境不同，就修改原本的應用程式邏輯。

例如，同一個 Laravel 專案

  • 透過 CLI 執行 php artisan migrate
  • 透過 PHP-FPM 處理 Web 請求
  • 透過 CLI 執行排程或背景任務

雖然使用的 SAPI 不同，但實際執行的仍然是同一份 PHP 應用程式。

PHP 常見的執行方式

PHP 提供多種 SAPI 實作，以支援不同的執行環境。其中 CLI、CGI 與 FPM 是 PHP 執行架構時最常接觸的幾種方式。

CLI

CLI（Command Line Interface）是專門用於命令列環境的 SAPI，透過 PHP CLI 執行檔，可以直接在終端機執行 PHP 程式，不經過 Web Server。

CLI 常見的使用場景：

  • Laravel Artisan 指令
  • Cron 排程工作
  • 自動化腳本
  • 背景工作與命令列工具

例如

執行 Artisan 指令時，PHP CLI 會啟動 PHP Runtime，再載入 Laravel 專案並執行對應的指令。

CLI 的特點：

  • 不需要 Web Server
  • 直接透過作業系統命令列啟動
  • 主要使用標準輸入、標準輸出及命令列參數

CGI

CGI（Common Gateway Interface）是 Web Server 呼叫外部程式處理請求的規範。PHP 透過 php-cgi 提供這項能力。

CGI 常見於早期 PHP Web Server 整合架構，現今新專案較少使用。

FPM

FPM（FastCGI Process Manager）是 PHP 提供的 FastCGI 實作及 Process Manager，提供 PHP FastCGI 執行環境，並負責管理 PHP 執行程序，讓 Web Server 能夠將 PHP 請求交由 PHP-FPM 處理，常見的 Nginx + PHP-FPM 部署架構，就是透過 PHP-FPM 執行 PHP 應用程式。

FPM 的特點：

  • 主要用於 Web 請求處理
  • 通常搭配 Nginx 等 Web Server 使用
  • 使用 FastCGI 作為整合方式
  • 提供 PHP 程序管理能力
  • PHP-FPM 本身包含對應的 FPM SAPI

健忘筆記

CGI（Common Gateway Interface）與 FastCGI（Fast Common Gateway Interface）都是讓 Web Server 與外部程式溝通的機制，主要差異在於 CGI 是一個 Request 啟動一個 Process，而 FastCGI 則是 Process 長駐，多個 Request 重複使用。

不同 SAPI 與執行方式的比較

CLI、CGI 與 FPM 都能執行 PHP 程式，但它們的定位及使用場景不同。

執行環境命令列、排程Web Server 整合環境FastCGI 執行環境
Web Server不需要通常需要通常需要
啟動方式命令列直接啟動CGI 執行程式PHP-FPM 服務

PHP 整體執行架構

PHP Runtime 負責執行 PHP 程式，而 SAPI 負責讓 PHP Runtime 能夠整合不同的外部執行環境，不同 SAPI 提供不同的執行入口，但最後都是透過 PHP Runtime 執行 PHP Application。

  • SAPI： 提供不同外部環境與 PHP Runtime 之間的整合介面
  • PHP Runtime： 提供 PHP 程式執行所需的環境
  • PHP Application： 實際開發的 PHP 程式，例如 Laravel 專案

結論

PHP 程式碼並不是直接由作業系統執行，而是透過 PHP Runtime 提供的執行環境，由 Zend Engine 負責核心的程式執行工作。SAPI 則扮演 PHP Runtime 與外部環境之間的整合介面，讓 PHP 能夠適應不同的執行場景。

本文以 PHP 8.x 為基準，各 SAPI 的細節與預設值可能隨版本調整，實際環境應以官方手冊為準。
