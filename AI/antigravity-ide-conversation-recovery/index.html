【Antigravity IDE】恢復 AI agent 對話紀錄

2026-10-07-回覆文章分享

本篇重點

  • antigravity 對話紀錄消失不一定代表實際資料遺失
  • 刪除舊對話、重新啟動 IDE，以及建立新 AI agent 對話，都出現對話紀錄無法持續保存的問題
  • antigravity-conversation-fix 可掃描既有對話資料並重建 Antigravity IDE 的 sidebar conversation index

先前記錄過 Antigravity 2.0 改版後 IDE 消失，以及透過新的 Antigravity IDE 恢復原本 IDE 與 AI agent 對話資料的過程，詳細說明可以查看【Antigravity】自動更新後編輯器因此消失，如何恢復原本的編輯器與設定。

本次問題不同於前一次的版本或資料夾遷移問題，而是 Antigravity IDE 可以正常使用，但 AI agent 對話紀錄在重新啟動後無法維持。

對話消失問題

問題背景

當天正常使用

Antigravity IDE 當天使用時，AI agent 對話功能正常，能正常對話，對話列表也正常顯示。

隔天開啟後消失

隔天重新開啟 Antigravity IDE，前一天建立的 AI agent 對話全部沒有出現在對話列表中。

此時檢查 C:/Users/[username]/.gemini/antigravity-ide/ 發現 brain 與 conversation 資料夾中仍存在前一天修改過的檔案。

因此可以確認當時看到的現象是：

項目狀態
AI agent 對話IDE 對話列表中看不到
brain 和 conversation 資料仍存在
實際檔案時間有前一天的修改紀錄

因此問題比較接近「本機資料仍存在，但 Antigravity IDE 沒有正常顯示」的狀態，而不是單純的對話檔案遺失。

嘗試刪除舊對話

當時編輯器中約有二十幾則對話，因此考慮是否存在對話顯示數量相關的限制。實際嘗試刪除大部分舊對話，再重新啟動 Antigravity IDE，結果前一天的對話仍然沒有出現，因此無法證明問題與對話數量有關。

新對話也無法保留

接著重新建立新的 AI agent 對話，觀察新建立的對話是否可以正常保存，結果隔天重新開啟 Antigravity IDE 後，新建立的對話再次消失，更特殊的是先前已經刪除的舊對話反而重新出現。

  • 刪除的舊對話並沒有如預期持續保持刪除狀態。
  • 新建立的對話無法正常出現在下一次啟動後。
  • 本機對話相關資料仍然存在。
  • 問題並非單純「某一個對話檔案損壞」。

當時沒有足夠資料直接判定 Antigravity IDE 內部的確切原因，因此沒有將「對話數量限制」或其他內部機制視為確定結論。

antigravity-conversation-fix 解決對話遺失問題

GitHub Repository：FutureisinPast/antigravity-conversation-fix

Repository 說明指出，Antigravity 的對話資料與 sidebar 顯示索引是分開處理的。對話檔案可能仍存在於使用者資料目錄，而 sidebar 則使用 app data 中的 SQLite database 建立顯示索引，因此，當對話資料仍存在，但 sidebar 無法正常顯示時，可以透過重新掃描對話資料並重建 index 的方式恢復。

Windows 環境使用方式

目前 Repository 提供 Windows .exe 檔案，不需要另外安裝 Python。

關閉 Antigravity

完全關閉 Antigravity 或透過工作管理員確認 Antigravity 已經完全結束。

下載工具

從 Repository 的 Releases 下載 Antigravity_Conversation_Fix.exe

執行工具

直接雙擊 Antigravity_Conversation_Fix.exe，工具會開啟終端機並掃描現有對話資料，接著重新建立 conversation index。

重新開啟 Antigravity

修復完成後重新開啟 Antigravity，即可確認 sidebar 中的對話是否恢復。

正常情況下不需要重新啟動 Windows；如果完整關閉 Antigravity 後仍未看到修復結果，才需要考慮重新啟動電腦。

使用時的注意事項

必須完全關閉 Antigravity

這是目前版本特別強調的安全條件，工具在偵測到 Antigravity 正在執行時會直接結束，不進行掃描與寫入。

不需要手動搬移對話資料

目前版本已經能自動偵測多種 Antigravity 資料夾名稱，並可以合併不同資料夾中的 conversation，因此不需要沿用早期版本需要手動處理資料夾的方式。

防毒軟體誤判

Repository 也特別提醒，PyInstaller 建立的單檔 .exe 可能觸發部分防毒軟體的啟發式偵測。若對執行檔來源有疑慮，可以直接檢查 Repository 原始碼，或改用 Python 原始碼執行。

問題解決後

實際使用 antigravity-conversation-fix 後，原本幾個異常現象都獲得解決：

  • 舊對話可以正常重新出現在列表。
  • 原本刪除後又重新出現的對話狀態恢復正常。
  • 新建立的 AI agent 對話可以在重新啟動後維持。
  • 對話列表可以依照時間正常顯示。
  • 不需要重新建立原本的 AI agent 對話。

這次實際結果也驗證了當 Antigravity 的 conversation 檔案仍然存在，但對話列表看不到資料時，不能直接判定為對話遺失。

結論

本次問題並非單純刪除或遺失 AI agent 對話資料，而是實際觀察到 conversation 相關檔案仍存在，但 Antigravity IDE 無法在重新啟動後正確維持對話列表。經過檢查資料夾、刪除舊對話、重新啟動及建立新對話等方式後，問題仍持續發生。最後透過 antigravity-conversation-fix 重建 conversation index 後恢復正常。
